# 部署

镜像由 GitHub Actions 构建并发布到 `ghcr.io/sakurachiyo0v0/imagewall`（见 `.github/workflows/image.yml`）：

| 触发 | 发布的标签 |
|-|-|
| 推到 `main` | `latest`、`sha-<7 位>` |
| 打 `v1.2.3` 标签 | `1.2.3`、`1.2` |

推送前 CI 会先跑单元测试，测试不过不出镜像。镜像同时有 amd64 和 arm64。

## Docker Compose（推荐）

把 [`deploy/docker-compose.yml`](../deploy/docker-compose.yml) 放到 `<部署根>/imagewall/`，按需改图片目录：

```bash
cd <部署根>/imagewall
mkdir -p cache state && chown 1000:1000 cache state
docker compose pull
docker compose up -d
```

目录：

| 目录 | 内容 | 能删吗 |
|-|-|-|
| `cache/` | 缩略图 | 能。删了会按需重新生成，受 `IMG_CACHE_MAX_MB` 限制 |
| `state/` | 图片尺寸 `dims.json`，以后还有颜色等 | 不要删，备份这个。删了会在后台重新算 |

图片目录只读挂载，容器没有改动原图的权限。容器以 uid 1000 运行，`cache/` 和 `state/` 必须对它可写。

首次建目录一定要带上属主，否则容器写不进去，表现为缩略图全部 403/422、尺寸数据迁不过去：

```bash
mkdir -p cache state && chown -R 1000:1000 cache state
```

从「以 root 运行的旧容器」迁移过来时，`cache/` 下已有的子目录都是 root 的，要整体改一次：

```bash
chown -R 1000:1000 cache state && chmod -R u+rwX,go+rX cache state
```

### 升级与回退

```bash
docker compose pull && docker compose up -d
```

回退：把 `image:` 改成具体版本，比如 `ghcr.io/sakurachiyo0v0/imagewall:1.2`，再 `up -d`。

### 从「代码挂载」的旧部署迁移

旧部署是用一个现成的 Python 镜像、把 `app/` 挂进去跑。迁移：

1. 停掉旧容器（**先别删**，出问题能马上 `start` 回去），把它改名腾出名字：`docker rename imagewall imagewall-old`
2. 按上面建 `state/`，`cache/` 直接沿用旧的（缩略图格式没变，不用重新生成）
3. `docker compose up -d`。第一次启动时 `dims.json` 会自动从 `cache/` 复制到 `state/`，旧文件保留
4. 确认没问题后再删旧容器和旧的 `app/` 目录

## 环境变量

| 变量 | 默认 | 说明 |
|-|-|-|
| `IMG_DATA_ROOT` | `/data` | 图片所在的根目录 |
| `IMG_ROOTS` | `图片:漫画:素材` | 根目录下哪些子目录可以浏览，冒号分隔 |
| `IMG_CACHE` | `/cache` | 缩略图缓存 |
| `IMG_STATE` | 同 `IMG_CACHE` | 要长期保留的数据 |
| `IMG_CACHE_MAX_MB` | `8192` | 缓存上限，超了按最久未访问清理；`0` 不限 |
| `IMG_WORKERS` | `min(4, CPU 核数)` | 生成缩略图的并发数 |
| `IMG_PORT` | `8899` | 监听端口 |
| `IMG_SCAN_TTL` | `60` | 文件夹清单缓存多少秒 |

## 不用 Docker

```bash
pip install "Pillow>=10,<12"
IMG_DATA_ROOT=/path/to/images IMG_CACHE=./cache IMG_STATE=./state python app/server.py --port 8899
```

## nginx 反代

页面里的 URL 全是相对路径，挂在子路径下也能用：

```nginx
location = /wall { return 301 /wall/; }
location /wall/ {
    proxy_pass http://127.0.0.1:8899/;
    proxy_http_version 1.1;
    proxy_set_header Connection "";
    proxy_read_timeout 120s;
}
```

**不要加 `proxy_buffering off`**：大 JSON 清单经 nginx 会间歇 504。

nginx 本身跑在 Docker bridge 网络里时，`127.0.0.1` 指的是 nginx 容器自己，要换成能到宿主的地址（宿主在某个 Docker 网络上的网关 IP）。

外网访问前在 nginx 层加 `auth_basic`，或放在带访问控制的隧道后面；应用自身没有账号系统。

## 从原型升级

v1.0 的缓存键里加了规格和格式，原型生成的缩略图不会再被命中。它们的文件名格式和新的一样（`<2 位>/<38 位>.jpg`），
超过缓存上限时会按最久未访问被正常清掉。想立刻腾空间可以整体删掉缓存目录。

设置从原型的 `wall.settings.v1` 自动迁移（缩略图长边 → 清晰度档位）。
